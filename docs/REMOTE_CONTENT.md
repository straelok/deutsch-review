# Серверный каталог учебных материалов

Статус: этап завершён. Каталог `2026.09.27.2` опубликован в Supabase Storage,
а клиентская реализация и приёмка подэтапа 7.6 выполнены.

## Цель

Теория и статические упражнения по грамматике, числам, алфавиту и правилам
чтения должны обновляться с сервера без выпуска новой версии приложения.
Каталог является общим и доступным только для чтения. Пользовательские слова,
прогресс, ответы и занятия продолжают синхронизироваться отдельно по нику.

Локальные данные остаются основным источником. Приложение должно полноценно
работать без сети с последней проверенной локальной версией каталога, а при её
отсутствии — со встроенной версией из сборки.

## Границы этапа

В серверный каталог входят:

- двуязычная теория, таблицы, примеры и подсказки;
- статические грамматические упражнения и их варианты ответа;
- данные уроков по алфавиту, числам и правилам чтения;
- инструкции и известные параметры уже поддерживаемых типов заданий.

Серверный каталог не содержит пользовательских слов, отметок изученности,
статистики, очередей и результатов. Новый тип интерактивного задания или новое
поведение интерфейса по-прежнему требует обновления приложения.

Последовательное добавление новых тем курса не входит в этот этап: темы
публикуются только после того, как пользователь изучил их в школе и отдельно
попросил добавить.

## Текущий объём

На момент проектирования встроенные файлы занимают примерно:

- `topics.json` — 53 408 байт без сжатия, 15 193 байта в gzip;
- `exercises.json` — 422 298 байт без сжатия, 24 070 байт в gzip;
- вместе — около 476 КБ без сжатия и 39 КБ в gzip.

При таком объёме один сжатый пакет проще и надёжнее разбиения по темам. Делить
каталог на отдельные пакеты следует только после измеренного роста размера или
времени обработки.

## Размещение на сервере

Общий каталог размещается в Supabase Storage/CDN отдельно от снимков профилей:

```text
content/latest/manifest.json
content/versions/<content-version>/catalog.json.gz
```

Версионные пакеты неизменяемы. Публикация новой версии завершается обновлением
`latest/manifest.json`; благодаря этому клиент не увидит ссылку на ещё не
загруженный пакет. Откат выполняется переключением манифеста на ранее
опубликованную версию.

Пример манифеста:

```json
{
  "manifest_version": 1,
  "content_version": "2026.09.27.1",
  "schema_version": 1,
  "minimum_app_content_schema": 1,
  "bundle_path": "content/versions/2026.09.27.1/catalog.json.gz",
  "sha256": "<64 lowercase hex characters>",
  "compressed_size": 39000,
  "uncompressed_size": 476000,
  "published_at": "2026-09-27T12:00:00Z"
}
```

`content_version` определяет снимок материала, а `schema_version` — структуру
JSON. Клиент принимает только известную структуру и не пытается угадывать
значение неизвестных полей, влияющих на проверку ответа.

## Структура пакета

Пакет объединяет все связанные данные, чтобы они проходили проверку и
активировались атомарно:

```json
{
  "schema_version": 1,
  "content_version": "2026.09.27.1",
  "topics": [],
  "verbs": [],
  "exercises": [],
  "lesson_content": {
    "alphabet": [],
    "numbers": [],
    "reading_rules": []
  }
}
```

Существующие стабильные идентификаторы тем и упражнений сохраняются. Нельзя
повторно использовать ID упражнения после смыслового изменения задания:
изменённое задание получает новый ID. Идентификаторы тем и прогресса остаются
стабильными, пока тема сохраняет прежний смысл.

## Проверка при запуске

Проверка версии выполняется ровно один раз при каждом запуске приложения.
Она не использует TTL и не пропускается из-за недавней успешной проверки.

1. Приложение сразу открывает проверенный локальный каталог, а если его нет —
   встроенный каталог из сборки.
2. Первый кадр и основной интерфейс не ждут сеть.
3. После первого кадра приложение один раз запрашивает маленький манифест.
   Допускаются HTTP-кэширование, `ETag` и ответ `304`, но запрос выполняется при
   каждом запуске.
4. Если версия и хеш совпадают с активным каталогом, полный пакет не
   скачивается.
5. Если версия новая и совместимая, пакет загружается во временный файл.
6. Размер, gzip, JSON, схема, ссылки, уникальность ID и SHA-256 проверяются вне
   UI-потока.
7. Только полностью проверенный пакет атомарно становится активным. При любой
   ошибке приложение продолжает использовать предыдущий каталог.

Ручная команда «Проверить обновления» может повторить проверку в уже открытом
приложении. Одновременные проверки объединяются в одну операцию.

## Локальное хранение и нагрузка

- Полный пакет скачивается только при изменении версии или хеша.
- Рабочий запуск не распаковывает и не разбирает каталог заново без
  необходимости; подготовленный проверенный результат кэшируется локально.
- Рекомендуемый начальный предел — 1 МБ для gzip и 5 МБ после распаковки.
  Превышение отклоняется до активации.
- Временные и повреждённые файлы удаляются после неудачной проверки.
- Хранится текущая версия и версии, на которые ссылаются незавершённые занятия.
  Остальные загруженные версии удаляются. Встроенная версия остаётся частью
  приложения и не дублируется очисткой.
- Сетевые ошибки, отсутствие места и несовместимый формат не замедляют вход в
  приложение и не повреждают активные данные.

## Занятия, версии и синхронизация

Каждое новое занятие сохраняет `content_version`. Оно использует именно тот
снимок заданий, на котором было создано, даже если позднее вышел новый каталог.
Существующие на момент миграции занятия получают версию встроенного каталога.

Если незавершённое занятие пришло с другого устройства, клиент сначала ищет
нужную версию локально, затем может скачать соответствующий неизменяемый пакет
из `content/versions`. Сервер не удаляет опубликованные версии, пока они могут
встречаться в синхронизируемых занятиях. Если версия недоступна, занятие не
пересобирается молча: пользователь получает понятное сообщение, а локальные
данные сохраняются.

Отметки изученности и статистика привязаны к стабильным ID тем и упражнений.
Обновление каталога не отмечает новые темы изученными и не открывает материал,
который пользователь ещё не проходил.

## Безопасная публикация

Публикация выполняется отдельным проверяемым Dart-инструментом через Supabase
Storage HTTP API. Supabase CLI для загрузки каталога не требуется:

1. проверить JSON, схему, уникальность ID, ссылки и ограничения размера;
2. собрать единый пакет и gzip;
3. вычислить SHA-256 и фактические размеры;
4. загрузить пакет по новому неизменяемому пути;
5. скачать или прочитать объект обратно и сверить хеш;
6. последним действием атомарно заменить `latest/manifest.json`.

Записывать каталог может только серверная роль. Публичное чтение допустимо,
так как учебный контент не является секретом. Секретный ключ не попадает в
приложение или репозиторий.

## Интерфейс

В настройках или экране сведений показываются версия каталога, дата публикации
и состояние последней проверки. Обновление устанавливается ненавязчиво; при
несовместимой схеме приложение предлагает обновить само приложение. Сбой
обновления не закрывает доступ к локальным урокам.

В первой итерации реализации все категории занятий также становятся свёрнутыми
по умолчанию. Действие категории — «Продолжить урок», «Следующий урок» или
«Добавить урок» — остаётся доступным в заголовке.

## План реализации

### 7.1. Формат и публикация

- Зафиксировать JSON Schema манифеста и пакета.
- Создать валидатор и сборщик gzip-пакета из текущих ресурсов.
- Добавить безопасную публикацию неизменяемой версии и манифеста в Supabase.

### 7.2. Локальный каталог

- Добавить хранилище версий и атомарную активацию проверенного пакета.
- Сохранить встроенный каталог как обязательный offline-fallback.
- Добавить очистку временных и неиспользуемых версий.

### 7.3. Обновление при запуске

- Выполнять один запрос манифеста после первого кадра при каждом запуске.
- Не скачивать пакет при совпадении версии и хеша.
- Загружать, проверять и активировать новую версию без блокировки UI.

### 7.4. Версионирование занятий

- Сохранять `content_version` в занятии и облачном снимке.
- Продолжать старые занятия на исходной версии каталога.

### 7.5. Статус и UI

- Показывать версию, дату, статус и ручную проверку обновлений.
- Сворачивать категории занятий по умолчанию.

### 7.6. Приёмка

- Первый offline-запуск работает на встроенном каталоге.
- Запуск с кэшем сразу открывает интерфейс и делает одну проверку манифеста.
- Неизменившаяся версия не вызывает скачивание полного пакета.
- Валидное обновление активируется атомарно.
- Неверный хеш, JSON, ссылки, размер и несовместимая схема отклоняются.
- Незавершённое занятие продолжается на сохранённой версии после обновления и
  после синхронизации на другое устройство.
- Очистка не удаляет версии активных занятий.
- Откат манифеста возвращает предыдущую версию.
- Android и Windows сохраняют полную offline-first работу и пользовательский
  прогресс.
