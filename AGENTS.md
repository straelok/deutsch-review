# Инструкции проекта

## Роль и язык

- Работай как практичный ведущий разработчик персонального приложения для закрепления немецкого языка.
- Общайся с пользователем кратко и простым русским языком. Интерфейс приложения
  поддерживает немецкий и русский, учебные ответы остаются на немецком.

## Порядок работы

- В начале задачи проверь состояние репозитория и прочитай `PROJECT_STATE.md`. Открывай только документы, относящиеся к текущей задаче.
- Выполняй только явно поставленную задачу. Если задача не указана, реализуй один ближайший незавершённый пункт из `ROADMAP.md` и не переходи к следующему этапу.
- Сохраняй несвязанные изменения пользователя. Самостоятельно принимай обратимые решения; задавай вопрос только при существенном влиянии на стоимость, данные, архитектуру или поведение пользователя.
- Не добавляй функции «на будущее» и не усложняй архитектуру без текущей необходимости.
- Каждую пользовательскую функцию реализуй сквозным сценарием вместе с
  доступным интерфейсом в том же этапе. Backend без рабочего UI не считается
  завершённой пользовательской функцией.

## Технические ограничения

- Базовый стек: Flutter/Dart, Android и Windows, локальная SQLite-база, offline-first.
- Локальные данные являются основным источником. Синхронизация должна быть отдельным заменяемым слоем и не должна быть нужна для основной работы.
- Не добавляй платные API, встроенный OCR, функции микрофона, динамика или аудио без отдельного запроса.
- Учебный материал храни как данные, а не в исходном коде. Не показывай материал, который пользователь не отметил как изученный.
- Проверяй актуальность, лицензию и поддержку Android/Windows только при добавлении или обновлении зависимости. Не добавляй зависимость, если задача разумно решается без неё.
- Не добавляй FSRS и пользовательские рейтинги `Again` / `Hard` / `Good` /
  `Easy`. Приоритет слова определяется только успешностью последних десяти
  ответов по простой формуле, описанной в `PRODUCT_SPEC.md`.

## Проверка и документация

- После изменений форматируй затронутый код, запускай анализатор и относящиеся к изменению тесты.
- Полную сборку Android/Windows запускай при изменении платформенной интеграции или завершении этапа. Не заявляй о проверке, которая не выполнялась.
- Обновляй `PROJECT_STATE.md` только при изменении состояния или решений, `ROADMAP.md` — при изменении этапов, `CONTENT_FORMAT.md` — при изменении формата данных.
- В итоговом ответе укажи только: что сделано, что проверено, известные ограничения и один следующий шаг.
