# Формат JSON слов Worttrieb

Текущая реализованная версия — `2`. Формат предназначен для слов,
существительных и глаголов. Импорт версии `1` остаётся совместимым.

## Минимальный файл

```json
{
  "format_version": 2,
  "words": [
    {
      "type": "word",
      "german": "lernen",
      "translation_ru": "учить"
    },
    {
      "type": "noun",
      "german": "Tisch",
      "translation_ru": "стол",
      "article": "der",
      "plural": "Tische"
    },
    {
      "type": "verb",
      "german": "lernen",
      "translation_ru": "учить"
    }
  ]
}
```

## Поля

- `format_version` — обязательное число `1` или `2`; экспорт использует `2`.
- `words` — обязательный массив.
- `type` — `word`, `noun` или `verb`. Версия `1` поддерживает только первые два.
- `german` и `translation_ru` — обязательные непустые строки. `german`
  содержит ровно один вариант и не допускает `;`. В `translation_ru` можно
  перечислить несколько русских переводов через `;`; пустые варианты между
  разделителями недопустимы.
- Для `noun` обязательны `article` (`der`, `die` или `das`) и `plural`.
- `example` и `note` — необязательные строки.
- `id`, `created_at` и `updated_at` необязательны при импорте и добавляются при
  экспорте. Даты используют ISO 8601.

## Безопасность импорта

Весь файл проверяется до записи. Неизвестная версия или неверный элемент
отклоняют весь пакет. При повторном импорте приложение сначала ищет запись по
стабильному `id`, а затем — по сочетанию типа и немецкого написания с учётом
регистра. Полностью совпадающая запись пропускается, а изменённые перевод,
пример, заметка и типовые поля заменяют прежнее содержимое с сохранением
локального ID, даты добавления и истории ответов. Удалённая запись с тем же ID
восстанавливается. Перед сохранением приложение показывает число новых,
обновляемых и неизменившихся записей; добавления и обновления выполняются одной
транзакцией. Отсутствие записи в импортируемом файле ничего не удаляет.

## Глаголы и грамматический контент

Этап 5 добавляет тип `verb`, не меняя смысл пользовательских полей:

```json
{
  "type": "verb",
  "german": "lernen",
  "translation_ru": "учить",
  "example": "Ich lerne Deutsch."
}
```

Поле `german` содержит инфинитив. Произвольный `example` остаётся справочным и
не преобразуется автоматически в упражнение. Импорт версии 1 остаётся обратно
совместимым.

Встроенный грамматический контент хранится отдельно от пользовательского
импорта слов в версионируемых JSON-ресурсах. Минимальная запись упражнения
содержит стабильный ID, ID темы, целевую словарную лемму, тип задания, исходный
текст, проверяемую часть, правильный ответ и необязательное двуязычное
пояснение. Задание доступно только при изученной теме и наличии активной леммы
подходящего типа в словаре.

Поддерживаемые типы грамматических заданий:

- `text` — ввод пропущенной формы или короткого ответа;
- `choice` — выбор одного ответа, включая часть речи и поиск ошибки;
- `yes_no` — отдельный простой выбор `Ja` или `Nein`;
- `word_order` — последовательная сборка предложения из заданных токенов.

Запись может содержать `options`, двуязычную инструкцию и `required_item_type`.
Для `word_order` правильный ответ хранится полной строкой, а варианты —
отдельными токенами. Все варианты являются статическими данными и входят в
снимок очереди по стабильному ID; пользовательский пример слова упражнения не
создаёт.

Текущая версия банка упражнений — `2`. Загрузчик сохраняет совместимость с
версией `1`, где отсутствующие поля означают текстовый ввод и требование
глагола.

## Планируемый серверный пакет

В этапе 7 текущие встроенные темы, упражнения и уроки алфавита, чисел и правил
чтения будут собираться в единый версионируемый `catalog.json.gz`. Это отдельный
общий каталог только для чтения; он не входит в пользовательский импорт слов и
в снимок синхронизации профиля.

Маленький `manifest.json` содержит версию формата, версию контента, минимальную
совместимую схему приложения, путь к неизменяемому пакету, SHA-256, размеры и
дату публикации. Приложение проверяет манифест один раз при каждом запуске после
первого кадра, но загружает полный пакет только при изменении версии или хеша.

Планируемая оболочка пакета:

```json
{
  "schema_version": 1,
  "content_version": "2026.09.27.1",
  "topics": [],
  "verbs": [],
  "exercises": [],
  "lesson_content": {
    "alphabet": [],
    "numbers": [],
    "reading_rules": []
  }
}
```

Пока этап 7 не реализован, текущими источниками остаются встроенные JSON-файлы.
Полная архитектура, правила версий и критерии приёмки описаны в
`docs/REMOTE_CONTENT.md`.
